MCP Server 怎么接国内模型

2026-11-17 · 海桥

连着帮人配了七八台机器之后，我发现同一个误会反复出现：很多人以为"接 MCP"和"接国内模型"是一件事，其实它们管的是两条不同的线。搞混之后，配置就会写在一个用不上的地方，然后报错看起来毫无道理。

先弄清你在配哪一样

客户端要发请求给模型，需要一个地址、一把钥匙、一个模型名。这三样凑齐，模型那边就通了。

客户端要能读文件、查数据库、调你自己的接口，这部分跟模型无关，走的是 MCP。MCP server 是给客户端加工具的地方。

两件事都得有，做法就分成两种：装两个东西分别配；或者找一个既能当 OpenAI 兼容端点、又对外提供 MCP 工具的东西。后面这种就是我写的那个，不过先把通用的部分说完，你不用它也能照着配。

三样东西从哪拿

地址和 key 在厂商控制台。这里唯一容易出错的是模型名，因为教程里的名字经常已经过期。别信任何文章（包括这篇），直接问服务端：

curl -H "Authorization: Bearer $KEY" $BASE/models

返回里的 data[].id 就是能用的值。本机 ollama 没有这个顾虑，ollama list 显示什么就写什么，一个字符都别改。

配置文件长什么样

下面这段是给桥用的，你可以只看结构：

{
  "providers": {
    "deepseek": {
      "base_url": "https://api.deepseek.com/v1",
      "api_key_env": "DEEPSEEK_API_KEY",
      "models": ["deepseek-chat"]
    },
    "local": {
      "base_url": "http://127.0.0.1:11434/v1",
      "discover": true
    }
  }
}

有两个地方值得说。key 这里写的是环境变量名，不是 key 本身。原因很实际：配置文件会被提交、被丢进压缩包、被同步到网盘，key 混在里面，早晚要泄露一次。

discover 是让程序自己去问端点有哪些模型，问不到就退回配置里的值。这是被人问烦了才加的：几乎每个来找我的人，第一次都是模型名写错。

注册到客户端

{
  "mcpServers": {
    "bridge": {
      "command": "python",
      "args": ["D:\\mcp-bridge\\server.py", "--config", "D:\\mcp-bridge\\config.json"],
      "env": { "DEEPSEEK_API_KEY": "sk-..." }
    }
  }
}

Claude Code 是 ~/.claude.json 或者项目下的 .mcp.json，Cursor 是 ~/.cursor/mcp.json。路径必须写绝对路径，用相对路径的十次有九次找不到文件。

改完要重启客户端。这一点没有例外，我试过等它自己刷新，等了半小时。

报错怎么读

你看到的多半是先做这个
401key 没进客户端进程，或者地址里 /v1 写错curl 直连验证，再回来查 env
404 / model not found模型名不匹配打一次 /models，抄 id
转圈然后超时HTTP/2 协商或代理层curl -v 看卡在哪一步；切 HTTP 1.1

确认它真的通了

我习惯跑三条命令，顺序是从便宜到贵：

python test_stdio.py          # 协议自检，七项
python server.py --doctor     # 环境体检，十七项
python server.py --report 1   # 账本里有没有记录

第一条过了说明协议通，第二条过了说明环境对，第三条出数说明调用确实发生了。三条都对但客户端还是不认，那问题一定在客户端读配置这一步，不在服务端。
