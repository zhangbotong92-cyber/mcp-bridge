MCP Server 怎么接国内模型：一步一步配

2026-11-17 · 海桥 · 配置片段可直接复制，命令都实测过

这篇只解决一件事：让你的 MCP 客户端（Claude Code / Cursor / Cline）调到国内的模型。不讨论"为什么要 MCP"，直接给能跑的东西。

第 0 步：先确认你要的是哪一层

你想要的要配的是
客户端能用国内模型发请求一个 OpenAI 兼容的 模型端点（Base URL + Key + 模型名）
客户端能调用外部工具（读文件、查库、调接口）一个 MCP server
两者都要能同时做这两件事的桥（下文给的就是）

第 1 步：拿到三样东西

Base URL   例如 https://api.deepseek.com/v1
API Key    各家控制台自己签
模型名     从 /models 接口拿，不要照抄教程

取模型名这一步别猜：

curl -H "Authorization: Bearer $KEY" $BASE/models

返回里 data[].id 就是能用的名字。本地 ollama 同理：ollama list 显示什么就写什么。

第 2 步：写配置文件

{
  "providers": {
    "deepseek": {
      "base_url": "https://api.deepseek.com/v1",
      "api_key_env": "DEEPSEEK_API_KEY",
      "models": ["deepseek-chat"],
      "prices": { "deepseek-chat": { "in": 2.0, "out": 8.0 } }
    },
    "local": {
      "base_url": "http://127.0.0.1:11434/v1",
      "discover": true,
      "models": []
    }
  }
}

两个关键决定：

① key 写在环境变量名里（api_key_env），不要明码写进文件——文件会被提交、被分享、被备份。

② discover: true 让程序自己去问端点有哪些模型，省掉"名字猜错"这一整类问题。

第 3 步：注册到客户端

{
  "mcpServers": {
    "bridge": {
      "command": "python",
      "args": ["/绝对路径/server.py", "--config", "/绝对路径/config.json"],
      "env": { "DEEPSEEK_API_KEY": "sk-..." }
    }
  }
}

文件位置：Claude Code 用 ~/.claude.json 或项目里的 .mcp.json；Cursor 用 ~/.cursor/mcp.json。

改完必须重启客户端，MCP 配置不做热加载；路径必须是绝对路径。

第 4 步：三个高频报错怎么读

报错实际原因动作
401 / Unauthorizedkey 没进客户端进程，或 base 多/少了 /v1先用 curl 直连验证，再检查客户端 env 段
404 / model not found模型名不匹配打一次 /models，原样抄 id
超时 / local proxy failedHTTP/2 协商或代理层curl -v 看卡在 DNS/TCP/TLS；客户端切 HTTP 1.1

第 5 步：确认真的通了

python test_stdio.py      # 协议自检 7 项
python server.py --doctor # 环境体检 17 项
python server.py --report 1   # 看账，确认每次调用都记下来了
